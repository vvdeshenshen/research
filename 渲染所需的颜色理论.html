02色度学

2.1 三种视锥与亮度函数

颜色不是光的属性，是人眼对光谱的三维投影。视网膜上约 600–700 万个视锥分三类，S 锥峰值约 420 nm，M 锥约 530 nm，L 锥约 560 nm；S 锥只占 2% 左右，L:M 比例个体差异极大（实测有 76:20 和 51:44 两种极端）。约 9200 万个视杆负责暗视，峰值约 498 nm，不分辨颜色。"三刺激"这一事实决定了渲染只需三个通道就能骗过眼睛，也决定了三通道渲染的所有误差来源。

项目数值对渲染的意义
明视亮度函数 V(λ) 峰值555 nm，K_m = 683 lm/W光度学单位（lm、cd、lx、nit）全部由它定义，它就是 CIE 1931 的 ȳ(λ)，所以 XYZ 的 Y 分量就是亮度
暗视 V′(λ) 峰值507 nm，≈1700 lm/W夜景的"蓝移"（Purkinje 效应）不是渲染器自动产生的，要靠后期模拟
中间视觉范围约 0.01–3 cd/m²色貌模型（CIECAM 系列）只对 >5 cd/m² 的明视条件有效
Weber–FechnerΔI/I ≈ 常数（亮度约 1–2%，未从一手来源核实）等步长的线性编码在暗部浪费、在亮部不足，这是伽马与 PQ 存在的全部理由
Stevens 幂律（1957）感知亮度 ∝ I^0.33（暗背景大目标）到 I^0.5（点光源）CIELAB 的立方根、Oklab 的立方根、sRGB 的 1/2.4 都是这个幂律的不同近似
Barten 对比敏感度（1999）PQ 曲线按它拟合 0–10000 cd/m²12 bit PQ 全程低于可见阈值；10 bit PQ 在无噪声的 CG 图像上会可见条带，实拍因噪声掩蔽可接受

对线性光直接量化为什么不行：8 bit 线性在最暗一档（1/255 → 2/255）的相对步长是 100%，远超 1–2% 的韦伯分数，天空和暗部会出现明显条带；要让线性编码全程低于阈值需要 14–15 bit，所以中间缓冲用 FP16（尾数 10 bit 加指数，相对步长恒定约 0.1%），最终输出用 sRGB/伽马（8–10 bit）或 PQ/HLG（10–12 bit）。

2.3 CIE 1931 XYZ：一切颜色数据的公共坐标

  • 来源：Wright（1928，10 名观察者）与 Guild（1932，7 名）的匹配实验，原色 700 / 546.1 / 435.8 nm。CIE 把 RGB 配色函数线性变换为 XYZ，使三条函数非负且 ȳ(λ) = V(λ)。XYZ 的原色是虚构的，物理不可实现，这正是它能包住所有可见色的原因。
  • 色度坐标：x = X/(X+Y+Z)，y = Y/(X+Y+Z)。xy 色度图上马蹄形边界是单色光轨迹，任何实际显示器的色域都是这个马蹄内的三角形（或多边形）。
  • CIE 1976 u′v′：u′ = 4X/(X+15Y+3Z)，v′ = 9Y/(X+15Y+3Z)。比 xy 更接近感知均匀，比较色域面积时应优先用 u′v′。
  • 2° 与 10° 观察者：1931 是 2° 视场；1964 的 10° 观察者用于大面积色样；显示与渲染一律用 1931 2°。
  • CIE 170 锥基础观察者（2006/2015）：基于 Stockman–Sharpe 的生理 LMS 数据，可按年龄和视场参数化；研究用，渲染与显示标准仍以 1931 为准。

2.4 LMS 与色适应的生理基础

从 XYZ 到锥响应 LMS 的变换矩阵不止一个（Hunt–Pointer–Estevez、Bradford、CAT02、CAT16、CIE 2006），它们都是"把三刺激值旋转到更接近视锥的坐标"，差别在于是否做了"光谱锐化"以便白平衡更准确。色适应变换（CAT）都遵循 von Kries 假说：在某个 LMS 空间里按白点比例缩放三个通道。

3.5 感知均匀空间：Lab、Oklab、ICtCp

渲染里需要"两个颜色差多少"的地方不少：纹理压缩误差、UI 渐变插值、抗锯齿混合、色域映射、画质指标。XYZ 和线性 RGB 是物理量，欧氏距离与感知差异不成比例，于是有了感知均匀空间。

CIELAB（1976）：L* = 116 f(Y/Y_n) − 16，a* = 500[f(X/X_n) − f(Y/Y_n)]，b* = 200[f(Y/Y_n) − f(Z/Z_n)]；f(t) = t^(1/3)（t > 216/24389），否则 (24389/27)·t/116 + 16/116。L* 的立方根就是 Stevens 幂律的近似；ΔE76 是 Lab 中的欧氏距离，JND 约 2.3（Sharma 2003），ΔE2000 加了明度、彩度、色相权重与蓝区旋转项。Lab 的缺点是蓝色的色相线弯曲（蓝→紫），用它做色域映射或渐变会偏紫。

IPT（Ebner & Fairchild 1998）：XYZ→LMS，带符号幂 0.43，再线性组合；设计目标是等色相线笔直。后来的 ICtCp、Oklab 都沿用这个"LMS → 非线性 → 对立色"的三段结构。

3.6 色貌模型与 ACES 2.0

CIECAM02（2002）与 CAM16（2017；CIE 248:2022 标准化为 CIECAM16）在 CAT 之后加亮度适应与双曲压缩，输出明度 J、彩度 M、色相 h 等属性，可以把 Hunt、Stevens 效应直接建模。ACES 2.0（2025 年 4 月发布）的输出变换就在简化版 Hellwig 2022 CAM 的 JMh 空间里工作：ACES → JMh → 只对 J 做色调曲线 → 只对 M 做彩度压缩 → 在 J、M 上做色域压缩（复用 ACES 1.3 RGC 的 powerP 曲线）→ 白限制 → 显示编码。这是从"逐通道 S 曲线"到"在色貌空间里分别处理明度、彩度、色相"的范式转移，第 6 章会展开。

3.7 感知空间在图形里的实际落点

  • 纹理压缩编码器基本不用 ΔE：bc7enc/BC7E 的"perceptual"模式在加权 YCbCr 里度量（RGBA 权重 128/64/16/32），astcenc 的 -perceptual 只对法线贴图生效。
  • 画质指标：NVIDIA 的 ꟻLIP（HPG 2020）按观看距离与像素尺寸做 CSF 滤波，在 Hunt 调整后的 L*a*b* 里算色差，2021 年扩展为 HDR-ꟻLIP，是渲染论文比较图像的常用指标。
  • UI 与渐变：在 Oklab 里插值不会出现 sRGB 插值的"中间发灰"和 Lab 插值的"蓝变紫"。
  • 色域映射与色调映射：见第 6 章，Oklch/JMh 保色相是核心诉求。

4.2 伽马的历史与四条曲线

  • CRT 物理：亮度 ∝ 电压^γ，γ 约 2.35–2.55；电脑用 LUT 把系统伽马调到 1.8–2.2，NTSC 规定 2.2，PAL 2.8。人眼的感知非线性（Stevens 幂律，Ebner–Fairchild 的 0.43 指数即倒数约 2.33）恰好与 CRT 非线性互为近似逆，这是部分巧合、部分工程选择，结果是 8 bit "伽马编码"同时解决了 CRT 驱动和感知量化两个问题。
  • Rec.709 OETF（1990）：V = 4.5L（L < 0.018），否则 1.099L^0.45 − 0.099。BT.709 只定义相机侧 OETF，不定义显示 EOTF；因为有线性段，它整体"看起来像纯 1.9 幂"。Rec.2020 同形，12 bit 系统给出高精度常数 α = 1.09929682680944、β = 0.018053968510807。
  • BT.1886 EOTF（2011）：L = a·max(V + b, 0)^2.4，a、b 由白电平与黑电平导出，用来让平板"模拟 CRT 参考特性"；BT.2390 把参考白写成 100 cd/m²。
  • sRGB（HP + Microsoft 1996，IEC 61966-2-1:1999）：
编码：C' = 12.92 C                 (C  <= 0.0031308)
      C' = 1.055 C^(1/2.4) - 0.055  (C  >  0.0031308)
解码：C  = C'/12.92                (C' <= 0.04045)
      C  = ((C' + 0.055)/1.055)^2.4 (C' >  0.04045)

观看环境：80 cd/m²、D65、环境 64 lx、1% 眩光。分段的原因：纯幂函数在 0 处斜率无穷大，8 bit 下最暗约 20 级码值无法区分；线性段同时补偿眩光。1996 草案阈值 0.03928 有微小不连续，1999 版改为 0.04045 后近似连续，但斜率仍从 1/12.92 跳到 1/12.70。

  • Apple 伽马 1.8：Macintosh 长期用 1.8 解码，直到 Mac OS X 10.6（2009-09）改为 2.2 与 sRGB 对齐。Display P3（2015）用 P3 原色、D65 白点和 sRGB 的传递曲线。

4.5 线性工作流：为什么所有"加法"都要在线性光里做

光传输是线性的：f(x + y) = f(x) + f(y)。光照与多光源累加、Alpha 混合、mip 与双线性/三线性滤波、MSAA/TAA resolve、bloom/DOF/模糊，数学上都是对辐射量求加权和，必须对线性值做。GPU Gems 3 第 24 章（Gritz & d'Eon，2007）的经典例子：

  • mip 变暗：纹素 1.0、1.0、0、0 平均为 0.5；若 0.5 被当作伽马 2.0 编码显示，只有 25% 亮度，粗 mip 整体变暗、级间"脉动"。
  • 光照衰减过陡：Lambert 球上 N·L = 0.5 的点应有一半亮度，伽马空间下显示为 0.25，明暗交界过锐、角落过暗；仅提亮画面无法修正。
  • 两个错误互相抵消的后果：不线性化纹理、也不编码输出，会出现肤色随光照漂移、高光叠到漫反射上变黄、次表面散射被压扁并在阴影边缘产生青绿光晕。
  • 高光变宽偏色：Hable 2010 指出伽马空间里高光从白→黄→绿漂移、衰减过软。

YCoCg（Malvar & Sullivan 2003）：Y = R/4 + G/2 + B/4，Co = R/2 − B/2，Cg = −R/4 + G/2 − B/4；YCoCg-R 用 lifting 做到可逆。Mavridis & Papaioannou 2012 的 Compact YCoCg Frame Buffer 每像素只存 Y 加一个色度通道（棋盘交错），读取时边缘导向去马赛克，用于压缩 G-buffer 与 HDR 目标带宽。

抖动（Gjøl，Playdead，GDC 2016）：截断量化平均偏暗 0.5 LSB；均匀噪声仍有"噪声调制"；正确做法是三角分布噪声（两个 hash 相加减 0.5）、可再加蓝噪声整形；在被量化的那个空间加噪声（写 sRGB 目标就先编码再加 1/255 级噪声，硬件自动编码时做 srgb2lin(dither(lin2srgb(c)))）；每帧换噪声图案配合 TAA；预乘 alpha 让噪声在混合前作用于正确的量，由此能混合小于 1/255 的颜色。天空、雾、光晕、衰减这类平滑渐变最易条带，有纹理噪声的区域会掩蔽。

4.9 Alpha、混合、抗锯齿与渐变

预乘 alpha（Porter–Duff，SIGGRAPH 1984）：直通 over 为 C_o = (α_s C_s + (1−α_s) α_d C_d)/α_o，预乘 over 为 C′_o = C′_s + (1−α_s) C′_d，GPU 混合因子 ONE, ONE_MINUS_SRC_ALPHA。Alvy Ray Smith（1995）指出非预乘的 over 不是封闭运算，每次合成都要除以新 alpha；预乘形式是仿射运算、满足结合律，层可以预先合成成 sprite。McDonald（NVIDIA，2013）的例子：红 (α=1) 与近透明绿 (α=0.1) 直通平均得到 (0.5, 0.5, 0, 0.55)，绿色被放大成边缘绿边；预乘后是 (0.5, 0.05, 0, 0.55)。Skia 的 surface 必须预乘，Core Graphics 的图像只支持预乘，glTF 纹理不预乘但用 over 混合。预乘应在线性空间做，整数格式下会损失暗色精度。

文字与 UI 的伽马：覆盖率是面积比例，是线性量，应在线性空间混合；但线性混合加伽马编码会让文字"变浅变细"，FreeType 因此有 stem darkening（只应在做伽马校正时启用）。Windows ClearType 的 GammaLevel 范围 1000–2200、默认 1900；Photoshop 的"Blend RGB Colors Using Gamma 1.00"默认关、"Blend Text Colors Using Gamma 1.45"默认开。这是渲染理论与排版习惯的妥协点：数学正确的线性混合，人眼反而觉得字细。

抗锯齿：覆盖率与 alpha 同理必须线性平均；sRGB 目标的 MSAA resolve 应先解码再平均再编码。HDR 下单个超亮样本会压倒其余样本，边缘失去抗锯齿、出现萤火虫，Karis（2013）提出 resolve 前做 T(c) = c/(1 + luma)、resolve 后做逆变换，等价于权重 1/(1 + luma) 的加权平均；UE4 TAA（2014）用同样的 luma 权重；Lottes（2016）用 max3(c) 代替 luma 做优化版。

渐变插值：CSS Color 4 规定未指定时默认在 Oklab 插值（legacy sRGB 颜色之间仍在伽马 sRGB 插值以兼容），带 alpha 先预乘，色相插值默认取短弧。color-mix(in oklab, …) 与 linear-gradient(in oklch, …) 可指定空间。Oklab 不适合做图像混合与滤波，那些仍该在线性 RGB 做。

5.3 EV100 与物理曝光（Frostbite 2014）

  • 曝光值定义：EV = log₂(L·S/K)，S 为 ISO，K 为反射式测光常数（ISO 2720 建议 10.6–13.4，Canon/Nikon/Sekonic 用 12.5，Minolta/Pentax 用 14）。EV100 即 S = 100 时的值，L = 2^EV100 · 12.5/100 = 2^(EV100 − 3) cd/m²。
  • 由相机参数：EV100 = log₂(N²/t) − log₂(S/100)，N 光圈、t 快门秒。曝光补偿：EV100′ = EV100 − EC。
  • 亮度对照（K = 12.5）：EV 0 → 0.125 cd/m²，3 → 1，6 → 8，9 → 64，12 → 512，15 → 4096，16 → 8192。无月夜约 −2 EV，室内 5–7 EV，阴天约 12 EV，晴天 14–15 EV。
  • 饱和度基准感光度：H_sbs = 78/S，78 这个常数让 18% 灰成像为 12.7%（留半档高光余量），L_max = 78·N²/(S·q·t)，镜头透过率 q = 0.65。
  • 曝光倍率：maxLuminance = 1.2 · 2^EV100（78/(100 × 0.65) = 1.2），exposure = 1/maxLuminance，finalColor = color × exposure。
EV100 = log2(aperture^2 / shutterTime * 100 / ISO)     // 相机参数
EV100 = log2(avgLuminance * 100 / 12.5)                // 自动曝光
exposure = 1 / (1.2 * 2^(EV100 - EC))

预曝光（pre-exposure）：光照缓冲用 FP16（最大 65504，最小正规化 6.1 × 10⁻⁵）；10 万 lx 的太阳与 0.001 cd/m² 的夜景无法同时装进去，所以 Frostbite 在每个光照 shader 的末尾乘上上一帧的曝光，再写入缓冲；单 pass 内各光源以 FP32 累加后再写 FP16。UE 4.19 起同样把上一帧曝光在写入 scene color 前乘入（Apply Pre-exposure 选项），Unity HDRP 一律以 EV100 表达曝光。

5.5 自动曝光

  1. 对数平均亮度（Reinhard 2002）：L̄ = exp((1/N) Σ log(δ + L))，缩放 L′ = (a/L̄)·L，key 值 a = 0.18（低调 0.09/0.045，高调 0.36/0.72）。
  2. 直方图法（Valve 2008，Frostbite、UE、HDRP 采用）：对 log 亮度建 64 桶直方图，取两个百分位之间的平均，剔除极亮极暗；UE 文档建议低 70–80、高 80–95，HDRP 默认 40–90。
  3. 时间适应：L_t = L_{t−1} + (L_target − L_{t−1})(1 − e^(−Δt·speed))；HDRP 默认暗→亮 3、亮→暗 1，与人眼"暗适应更慢"一致。
  4. 中灰锚点：18% 反射率（Zone V）；HDRP 目标中灰默认 12.5%，可选 14%、18%。
  5. 曝光必须在色调映射前：色调曲线的 toe/shoulder 固定在输入域并以中灰为锚，先乘曝光才能把场景中灰落在曲线线性段；之后再缩放会压扁肩部。Frostbite 把曝光前移到光照阶段后，管线末端不再乘曝光。
  6. 按像素亮度曝光的缺陷：10% 灰与 90% 灰的场景会得到相同曝光（反照率混入），按照度曝光更准但成本高。

6.3 色相问题：逐通道、仅亮度与中间路线

  • 逐通道曲线：饱和色随亮度上升向六个基色次色塌缩（蓝→青或紫、红→黄），暗部增饱和、亮部去饱和；Hable 认为后者是电影胶片的"特性"。
  • 仅亮度曲线：无色相偏移，但高光不趋白，色度溢出显示色域被裁剪（蓝通道最先裁）。
  • 中间路线：Lottes 的串扰；NVIDIA 2016 在 ACES 上做亮度/逐通道混合；Frostbite 2017 在 ICtCp 的亮度/色度上做显示映射，再与逐通道结果按 0.6 混合，并把特效重做成按色温索引的黑体色带；Khronos Neutral 与 Tony 以保色相加受控趋白为设计核心；AgX 用 inset/outset 几何解决；ACES 2.0 干脆在色貌空间里把明度、彩度、色相分开处理。
  • 局部色调映射：Reinhard 的 dodging-and-burning、Durand–Dorsey 2002 的双边滤波（log 亮度分 base/detail 只压 base）、Fattal 2002 的梯度域。游戏里直到 UE 5.0（2022）才有 Local Exposure：在 log 亮度上建 bilateral grid，参数 Highlight/Shadow Contrast（建议 0.6–1）、Blurred Luminance Blend（0.4–0.6）；Epic 建议 Lumen 场景一律开启。

  • 位置：ACES 术语里 LMT 在 scene-referred 线性空间、色调映射之前；ODT 之后的显示空间调色只用于 SDR LUT。UE 文档明确传统 LDR LUT"在 HDR 显示上不可靠"，Color Grading 面板的控件都在色调映射之前工作。
  • 3D LUT：16³/32³/33³；Frostbite 用 33³、10 bit，以 PQ 作 LUT 的分布函数（比较过 log、S-Log、LogC）。Unity 的内部 LUT 用 Alexa LogC（cut 0.011361、a 5.555556、b 0.047996、c 0.244161、d 0.386036、e 5.301883、f 0.092819；LinearToLogC = c·log₁₀(a·x + b) + d）。
  • ASC CDL：out = (in·slope + offset)^power，再 sat：luma + sat·(out − luma)。
  • Lift/Gamma/Gain（Hable 2017）：lerp(shadows, highlights, pow(src, gamma))；他建议的顺序是曝光 → 色彩滤镜 → 饱和度 → log 对比（以 log₂0.18 为枢轴）→ filmic 曲线 → 显示伽马 → LGG。逐通道操作可烘成 1D 表，跨通道操作才需要 3D LUT。
  • 白平衡：色温/色调两个滑块，本质是一次 CAT（第 3.3 节）。
  • 工作色域：UE 5.1（2022-11）引入 Working Color Space：sRGB、Rec.2020、AP0、AP1、P3-DCI、P3-D65 或自定义；纹理按来源色域自动转换；UE 的 tonemapper 内部始终在 AP1。OpenColorIO 在 UE 4.26 起有插件，Unity、Godot 无原生支持。

6.7 色域映射

  • 问题：在 Rec.2020/AP1 中渲染再输出到 sRGB/P3，矩阵变换后出现负值或 > 1 的分量；硬裁剪同时去饱和和偏色，最典型是饱和蓝在逐通道曲线或裁剪后 R、G 被抬升变成紫。ACES 1.1（2018）为此发过 Blue Light Artifact Fix LMT，1.3 的 RGC 取代了它。
  • AP1 工作空间的价值：AP1 包含 Rec.709、P3 和几乎全部 Rec.2020，素材进入 AP1 后极少出现负值，曲线在大色域里运算后再做一次统一的输出映射。
  • ACES 1.3 Reference Gamut Compression（2021）：在 AP1 中 A = max(R, G, B)，d = (A − RGB)/|A|；d < t 不变，否则按 powerP 曲线压缩；limit = [1.147, 1.264, 1.312]（青、品、黄方向），threshold = [0.815, 0.803, 0.880]，power = 1.2。
  • CSS Color 4：Oklch 中固定 L、h，对 C 二分到裁剪后 ΔE_OK < 0.02。
  • ACES 2.0（2025）：在 JMh 中沿恒定色相切片压缩，目标色域的"cusp"（基色/次色连线与边界交点）按色相查 1D LUT，reach 色域为 AP1，压缩曲线仍是 RGC 的 powerP；目标是 100/1000/4000 nit 显示之间的一致性。

7.3 漫反射、次表面与透射

  • 漫反射模型：Lambert σ/π；Disney/Burley 2012 的逆向反射项（F_D90 = 0.5 + 2·roughness·cos²θd，光滑表面掠射减半、粗糙表面最多 2.5 倍），Frostbite 做了重归一化；OpenPBR 采用能量守恒的 Oren–Nayar（EON，2024）。Disney 的 11 个参数：baseColor、subsurface、metallic、specular、specularTint、roughness、anisotropic、sheen、sheenTint、clearcoat、clearcoatGloss；清漆固定 IOR 1.5、无色。
  • 皮肤：Jimenez 2015 可分离 SSS 的默认 strength = (0.48, 0.41, 0.28)、falloff = (1.0, 0.37, 0.3)，红通道散射距离最远，这就是皮肤"红透"的来源；UE 的 Subsurface Profile 用同一组默认值；源码头文件警告"在非线性空间里做 SSS 会彻底毁掉它"。Christensen–Burley 2015 的扩散近似 s = 1.85 − A + 7|0.8 − A|³。OpenPBR 的 subsurface_radius_scale 默认 (1.0, 0.5, 0.25)。
  • 吸收：Beer–Lambert，glTF KHR_materials_volume 用 attenuationColor 与 attenuationDistance，T(x) = c^(x/d)。
  • 薄膜干涉：glTF KHR_materials_iridescence（2022），默认 IOR 1.3、厚度 100–400 nm，基于 Belcour–Barla 2017，在 Fourier 域对 Airy 求和做光谱抗锯齿再投到 Rec.709，因为"实时渲染器只有三个分量"。
  • 色散：glTF KHR_materials_dispersion（2024），dispersion = 20/V_d；Abbe 数：金红石 9.8、聚碳酸酯 32、钻石 55、水 55、冕牌玻璃 59。这是 RGB 渲染里最常见的"伪光谱"：按三个波长各算一次折射率。
  • 材质标准：Autodesk Standard Surface（2019）、OpenPBR Surface（Autodesk + Adobe，ASWF 托管，v1.1.2 2026-10），都以 MaterialX 节点图发布。

7.7 光谱渲染与 RGB 渲染的差距

真实过程是 ∫ρ(λ)E(λ)c̄(λ)dλ，RGB 渲染把 ρ 与 E 先投影成三元组再逐分量相乘，相乘与积分不可交换。pbrt-v4 的例子：sRGB 纯绿 (0, 1, 0) 自乘不变，同一颜色在 ACES2065-1 里是 (0.38, 0.82, 0.12)，平方后约 (0.14, 0.67, 0.01)，亮度下降且跑出可实现色，说明 RGB 乘积依赖工作空间原色。Ward 2002 测得：在主光源下预滤波反射率可把朴素 RGB 的 ΔE 误差降到 1/6；Meng 2015 证明要复现很多 RGB 颜色，反射光谱必须违反能量守恒。

光谱上采样：Smits 1999（7 个基光谱）→ Meng 2015 → Otsu 2018（PCA 聚类）→ Jakob–Hanika 2019（sigmoid(c₀λ² + c₁λ + c₂)，三系数，整个 sRGB 色域零误差，Mitsuba 3 与 pbrt-v4 采用，后者按 sRGB/P3/Rec.2020/ACES 各备 64³ 系数表）→ Mallett–Yuksel 2019（三条对应 BT.709 原色的基光谱，D65 下精确）。

哪些渲染器是光谱的：Manuka（Weta，2018 TOG，hero wavelength 采样，每路径 8 个波长，刻意不做荧光）、Mitsuba 3（spectral 变体，360–830 nm，每光线 4 波长；polarized 变体用 Stokes 向量，成本 1.5–2×）、pbrt-v4（默认每光线 4 个波长采样）、Maxwell、Octane（宣传光谱，完整光谱内核多次推迟，现状未核实）。Arnold（Arnold 7 起默认 ACEScg）、Cycles、Hydra Storm、V-Ray 是 RGB。需要光谱的场景：色散、荧光、薄膜与结构色、同色异谱光源下的材质、多次反弹后的饱和度、相机/观察者 CMF 模拟。

09汇合与判断

9.1 贯穿全文的几条主线

  1. 颜色是感知量，光是物理量，渲染在两者之间来回。 光照计算只能在物理量（线性辐射量）上做；存储、传输、显示和"看起来差多少"的判断要在感知量（伽马/PQ 编码、Lab/Oklab/JMh）上做。几乎所有颜色错误都是把这两类操作放错了空间。
  2. 三刺激既是便利也是债务。 RGB 渲染靠同色异谱才成立，代价是反射率 × 光源在 RGB 下不精确、金属 F0 依赖光源与工作空间、荧光灯显色无法表现。工作空间越宽（AP1）误差越小、负值越少，但不会消失；需要精确的地方只能上光谱。
  3. 位深的瓶颈在暗部。 韦伯分数 1–2% 决定线性 8 bit 不可用、FP16 够用、10 bit PQ 勉强够、12 bit PQ 全程够；抖动是最便宜的补救，而且必须在被量化的那个空间加。
  4. 色调映射的历史是从"一条曲线"走向"分别处理明度、彩度、色相"。 2010 年的 Hable 与 2014 年的 ACES 都是逐通道 S 曲线，附带色相偏移与六色塌缩；2017 年 Frostbite 转到 ICtCp，2022 年 AgX 用 inset/outset，2023 年 Tony 用 LUT，2024 年 Khronos Neutral 用 max-RGB 保色比，2025 年 ACES 2.0 直接在色貌模型的 JMh 里工作。
  5. HDR 显示没有改变渲染，改变的是输出端。 场景内部早已是 scene-linear 的 HDR；HDR 输出只是把色调映射的目标从 80–300 nit 换成 1000 nit 以上、把 sRGB 编码换成 PQ、把 Rec.709 换成 Rec.2020，再加上 paper white、headroom 与元数据这些以前不存在的参数。
  6. 色温不等于白点，6500 K 黑体不等于 D65。 引擎从色温取色相、白点固定 D65 是正确做法。

9.3 核实中纠正的常见说法

  • "UE3 是伽马空间光照"：UDK 文档显示 UE3 已用 sRGB 纹理与线性光照。
  • "Unity 3.0 引入线性光照"：能找到的最早文档是 3.5.1，3.0 无法确认。
  • "Half-Life 2 已是 gamma-correct"：未能证实；可证实的是 Valve 在 GDC 2008 描述了 DX9/DX10 硬件混合空间不同造成的问题。
  • Frostbite 的 HDR 调色与显示演讲是 GDC 2017，不是 SIGGRAPH 2017。
  • Call of Duty 的 HDR 显示管线出自 Paul Malin（WWII），Jimenez 2014 讲的是后处理。
  • Mass Effect Andromeda 不是第一个 HDR PC 游戏，Hitman、Resident Evil 7 更早。
  • Unity 的 HDR 输出在 HDRP 13.0 / Unity 2022.1，不是 2022.2；Bevy 的 Tony McMapface 默认始于 0.11 而非 0.12；Khronos PBR Neutral 发布于 2024 年 5 月而非 3 月。
  • 金的 F0 (0.944, 0.776, 0.373) 这组常见数值在任何一手来源里都找不到；Hoffman/RTR 给 (1.00, 0.71, 0.29)，Lagarde/UE 给 (1.000, 0.766, 0.336)。
  • "ACES 白 = D60"：ACES 白点 (0.32168, 0.33767) 约 6000 K，但 CIE 没有 D60 标准光源。

9.4 未核实项

韦伯分数 1–2% 与"线性需约 12 bit"的原始出处（Poynton FAQ 无法抓取）；Rec.601 系数源于 NTSC 1953 原色的推导；DCI-P3 的"2007"日期；Mitsuba 3 与 pbrt-v4 每光线 4 个波长；Arnold 无光谱模式；Octane 光谱内核现状；OKHSL 细节；HLG 扩展系统伽马的 κ = 1.111；BT.2408 的 203 cd/m² 参考白；Blender Filmic 2.80 / AgX 4.0 的默认版本（手册未写版本史）；OCIO 2010 开源与 2021 v2.0 的精确日期；"BF4 用 LogLuv 渲染目标"；Call of Duty AW/IW 的渲染目标格式；D3D9 sRGB 状态与 D3D10 DXGI sRGB 格式的引入日期；UE Working Color Space 的 5.1 版本号（来自第三方文档）；Hosek–Wilkie 的 UV 通道数。
